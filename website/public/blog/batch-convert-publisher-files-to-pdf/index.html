How to Batch Convert Publisher Files to PDF (Guide for IT Teams)

PubConv · 23 October 2026 · 8 min read

If you look after IT for a school, diocese, charity or small business, Publisher's retirement probably landed on your desk as "can you sort out all the .pub files?" This guide covers a repeatable way to do it, from finding the files to checking the results.

Step 1: Find every .pub file

Start with an inventory, so you know the size of the job and can report progress. On a file server or a PC with access to the shares, this PowerShell lists every .pub file with its size and date, and saves it as a spreadsheet:

Get-ChildItem -Path "D:\Shares" -Recurse -Filter *.pub -File -ErrorAction SilentlyContinue |
  Select-Object FullName, Length, LastWriteTime |
  Export-Csv "$env:USERPROFILE\Desktop\pub-inventory.csv" -NoTypeInformation

Don't forget OneDrive and SharePoint document libraries (sync them or use their search), staff laptops, and old USB backups.

Step 2: Decide what to convert

  • Archive copies (most files): convert to PDF and keep the original next to it.
  • Templates still in use: convert to PDF for reference, then rebuild them in Word or PowerPoint, as Microsoft suggests.
  • Duplicates and junk: the inventory usually shows plenty. Agree a policy before deleting anything.

Step 3: Convert in bulk

Option A: Microsoft's script (needs Publisher)

Microsoft publishes a sample PowerShell script, Convert-PubFileToPDF.ps1, that drives Publisher to export files or folders to PDF. It gives Publisher-perfect output, but it needs a PC with Publisher still installed, and Microsoft asks you to test and adapt it. It doesn't overwrite existing files, so clear or rename conflicts first.

Option B: LibreOffice headless (free)

LibreOffice can convert from the command line:

soffice --headless --convert-to pdf --outdir "D:\PDF" "D:\Archive\*.pub"

It's free and scriptable, but it doesn't recurse into subfolders by itself, and WordArt and linked newsletter text often come out wrong (see our test).

Option C: PubConv command line

PubConv includes pubconv-cli for scripted jobs. It walks a whole tree, writes each PDF next to its .pub (or to an output folder), and reports a result for each file:

pubconv-cli "D:\Archive" -r -o "D:\PDF" > "D:\PDF\conversion-log.txt"
  • -r includes subfolders; -o sets an output folder.
  • Each line says OK or FAIL with the file and the reason, which is easy to filter in a spreadsheet.
  • Exit code 0 means every file converted, 1 means some failed, 2 means a usage error. That's handy in scheduled tasks.
  • Everything runs locally; nothing is uploaded.

Prefer clicking? The PubConv window does the same: add a folder, choose an output, click Convert.

Step 4: Check the results

No converter is perfect, so spot-check before you sign the job off:

  1. Compare the number of PDFs with the inventory count.
  2. Open a sample from each year and each department.
  3. Look specifically at documents with WordArt headlines and multi-page newsletters, which are where converters most often fail.
  4. Re-run any failures individually, and keep the original .pub files in all cases.

Step 5: Communicate

Tell staff where the PDFs are, that the originals are kept, and who to contact if a document looks wrong. A short note saves a lot of support tickets.
